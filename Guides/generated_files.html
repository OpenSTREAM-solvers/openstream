Generated files and session directories

OpenSTREAM calculations can generate input files, session directories, logs, saved solver objects, exported data, and figures.

Understanding where these files are created is important for:

  • keeping source repositories clean;

  • avoiding accidental overwriting of previous calculations;

  • reproducing reported results;

  • separating temporary output from approved numerical references;

  • preventing generated files from being committed to Git.

This page describes the general file-management conventions used by OpenSTREAM. Individual tutorials, tests, and OpenSTREAM-database projects may define more specific output locations.

Input files

An OpenSTREAM calculation is constructed from model, numerical-option, geometry, and boundary-condition inputs.

These inputs can be read from existing files or generated by another workflow, such as OpenSTREAM-database.

Typical input paths include:

modelFilePath
optionsFilePath
geometryFilePath
bcFilePath

The complete paths should be passed explicitly when constructing an Inputs.InputSet object. Avoid relying on the current MATLAB working directory to locate maintained input files.

For example:

inputSet = Inputs.InputSet( ...
    modelFilePath = modelFilePath, ...
    modelID = modelID, ...
    optionsFilePath = optionsFilePath, ...
    optionsID = optionsID, ...
    geometryFilePath = geometryFilePath, ...
    geometryID = geometryID, ...
    bcFilePath = bcFilePath, ...
    sessionParentDir = sessionParentDir);

Maintained input files should remain separate from generated calculation output.

Session directories

Each calculation uses a session directory to store files associated with that solver execution.

The parent location is selected through:

sessionParentDir = '<output-folder>'

OpenSTREAM creates the calculation-specific session directory below this parent directory.

The session directory can contain, depending on the selected workflow and logging configuration:

  • calculation logs;

  • solver output;

  • copied or generated session input files;

  • exported numerical data;

  • saved solver objects;

  • files required for restarting or reviewing the calculation.

Users should select sessionParentDir explicitly for maintained workflows. This avoids creating output in unexpected locations and makes it easier to remove or archive completed calculations.

A local exploratory calculation can use:

sessionParentDir = fullfile(pwd,'outputs');

A maintained application should normally use a project-specific output location rather than depending implicitly on pwd.

Overwriting an existing session

The overwriteSessionFiles option controls whether an existing session directory can be replaced.

For example:

inputSetOpts = { ...
    'overwriteSessionFiles',true, ...
    'LOGMODE','BOTH'};

When overwriteSessionFiles is true, OpenSTREAM can remove an existing session directory before creating the new calculation session.

A warning similar to the following can be displayed:

Warning: <session-directory> was removed.

This message indicates that the existing calculation directory was deliberately replaced. It does not by itself indicate a solver failure.

Use overwriteSessionFiles = true when a workflow is intended to be rerun reproducibly and earlier generated output can be replaced.

Use overwriting with caution when:

  • previous results have not been reviewed or archived;

  • several calculations share the same session location;

  • a session contains manually added files;

  • the output is required as an approved numerical reference;

  • another MATLAB process may be using the directory.

A workflow should not rely on overwriting as a substitute for unique and well-organized output locations.

Logging

The InputSet logging configuration is passed through LOGMODE.

For example:

inputSetOpts = { ...
    'overwriteSessionFiles',true, ...
    'LOGMODE','BOTH'};

The selected logging mode determines how calculation information is made available during solver execution. Use the same logging configuration when comparing or reproducing calculations whenever the log content forms part of the review procedure.

Logging settings do not replace convergence checks. A calculation should be evaluated using the final solver state and the relevant pointwise, steady-state, or transient convergence information.

Saving solver objects

OpenSTREAM solver objects can be saved when a persistent result is required.

A saved solver object can retain convenient access to calculated fields, input information, and post-processing functionality. However, saved objects can depend on:

  • the OpenSTREAM source revision;

  • MATLAB class definitions;

  • Python integration;

  • CoolProp compatibility;

  • result-object organization;

  • serialization behavior.

A saved solver object should therefore not be the only record retained for a calculation.

For reproducibility, also retain:

  • the original input files or dataset records;

  • the solver framework;

  • the physical and closure models;

  • nondefault model parameters;

  • numerical settings;

  • convergence criteria and status;

  • the OpenSTREAM version or commit;

  • the supporting script or Live Script.

OpenSTREAM-database outputs

OpenSTREAM-database generates OpenSTREAM input and result folders for the selected dataset case.

A dataset package can contain generated folders such as:

+DatasetName/
├── +inputs/
│   └── case-000001/
└── +results/
    └── case-000001/

The generic Dataset implementation provides the generated model, geometry, numerical-option, and boundary-condition file paths to Inputs.InputSet. The result folder is used as the session parent directory for the calculation.

The dataset source file, dataset class, plotting methods, and README remain maintained source content. Generated +inputs and +results folders are temporary calculation artifacts and should normally be excluded from version control.

Lightweight OpenSTREAM-database cases do not use a dataset-specific XML or JSON package. Their generated-file location should be defined by the workflow so that output is not created unexpectedly in the repository root.

The OpenSTREAM-database runCase wrapper also provides a saveResultsToFile option. This controls whether the calculated solver object is saved after execution. It is an OpenSTREAM-database workflow option and should not be confused with the core OpenSTREAM overwriteSessionFiles setting.

Sandbox calculations

The OpenSTREAM sandbox folder is intended for temporary exploratory calculations.

Generated input files, session directories, logs, figures, saved solver objects, and local scripts created in the sandbox should remain local and should not be committed.

Copy and rename any *_default.m template before modifying it.

Reusable work should be moved to the appropriate maintained location:

  • general learning workflows belong in the tutorials;

  • automated verification belongs in the tests;

  • reusable implementation changes belong in the corresponding source package;

  • publication and experimental-validation workflows belong in OpenSTREAM-database.

Test outputs

Automated tests can generate temporary files, logs, session directories, CSV files, and saved solver objects under test-specific output folders.

Generated test output should not normally be committed.

Approved numerical reference solutions are different from temporary test output. Reference solutions form part of the regression baseline and should be stored only in the designated reference location.

A numerical reference should be updated only after the calculated difference has been understood, justified, and reviewed.

Version-control policy

Generated files should normally be excluded using repository .gitignore rules.

Before committing a change, review tracked, untracked, and ignored files:

git status
git status --short
git status --ignored --short

Do not commit:

  • temporary session directories;

  • generated input or result folders;

  • logs;

  • MATLAB autosave files;

  • local sandbox scripts;

  • saved solver objects that are not approved references;

  • exported figures or data that can be regenerated;

  • obsolete output copies.

Do not use git add . without first reviewing all modified and untracked files.

Moving or deleting generated files

Generated output can normally be deleted after the calculation has been reviewed, provided that the inputs and workflow required to regenerate it have been retained.

Before deleting a session, confirm that it does not contain:

  • the only copy of an input modification;

  • an approved numerical reference;

  • manually prepared post-processing data;

  • results required for a publication or technical report;

  • diagnostic information needed to investigate a failure.

When a calculation must be archived, store the associated input files, software versions, settings, convergence information, and execution workflow together with any retained results.

Recommended workflow

For a reproducible calculation:

  1. Select an explicit session parent directory.

  2. Keep maintained inputs separate from generated outputs.

  3. Decide whether an existing session may be overwritten.

  4. Run the calculation with the intended logging configuration.

  5. Review the final convergence state.

  6. Review generated inputs and outputs.

  7. Retain the information needed to regenerate the calculation.

  8. Archive only results that cannot be regenerated easily or that form an approved reference.

  9. Remove or ignore temporary output before committing repository changes.

Troubleshooting

Unexpected output location

If generated files appear in an unexpected folder:

  1. Inspect sessionParentDir.

  2. Check whether any input or output path depends on pwd.

  3. Display the current working directory using pwd.

  4. Use fullfile and explicit repository or project paths.

  5. Confirm that a lightweight OpenSTREAM-database workflow defines an appropriate generated-file location.

Existing session was removed

If OpenSTREAM reports that a directory was removed, check whether:

overwriteSessionFiles = true

was supplied to Inputs.InputSet.

The message indicates replacement of the previous session output. Set a different session parent directory or session identifier if the previous results must be retained.

Existing session cannot be replaced

If an existing session prevents execution:

  • review whether overwriting is appropriate;

  • select a new session parent directory;

  • remove or archive the existing directory manually;

  • confirm that no other MATLAB process is using the same session;

  • verify write permission for the output location.

Output should not be committed

If a generated file is already tracked but should remain locally:

git rm --cached <path>

Then add the path to .gitignore, commit the removal from the index, and retain the local working copy.
